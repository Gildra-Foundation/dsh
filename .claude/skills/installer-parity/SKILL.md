# Паритет установщиков Gildra DSH

Один конвейер установки написан трижды: `install/macos-install.command` (zsh),
`install/windows-install.ps1` (PowerShell 5.1 — сначала прочитай скилл
`powershell-51`), `install/linux-server-install.sh` (bash). Плюс по три версии
лаунчеров: `Start-GildraDSH.{command,ps1,server.sh}`,
`Update-GildraDSH.{command,ps1,cmd}`, `dsh-gildra{,-server,.ps1}`. Логика,
изменённая в одном файле и забытая в остальных, — главный источник дрейфа в
этом репозитории.

## Общий конвейер (одинаков на всех платформах)

читать `config/kit.json` → скачать Node (SHA-256 из манифеста) →
corepack/pnpm → скачать исходники DSH по commit → сборка со staged swap и
backup → codegraph → скопировать лаунчеры в `bin/` →
`scripts/configure-profile.mjs` → записать маркер версии.

## Правила

1. **Изменил шаг — пройди все три файла** и соответствующий лаунчер каждой
   платформы. Если шаг платформенно неприменим, оставь комментарий почему —
   отсутствие шага без комментария неотличимо от забытого.
2. **Никаких версий и списков в установщиках.** Версии, плагины, хеши — только
   из `kit.json`; `verify.sh` грепает установщики на утёкшие спеки и упадёт.
3. **Синхронные константы.** Порт 3080, порт Ollama 11434 и путь
   `source/apps/cli/lib/bin.js` продублированы по ~6–9 файлов (установщики,
   лаунчеры, `HarnessService.swift`, `sync-server-fleet.mjs`). Меняешь одно —
   грепни по репо и обнови все вхождения.
4. **Не копируй существующий дрейф как образец.** Известные расхождения,
   которые НЕ являются эталоном: staging при распаковке Node есть только в
   Linux-версии (правильный паттерн — staged+rename везде); guard «небезопасного
   корня» на Windows/Linux обходится хвостовым слэшем (macOS нормализует через
   `:A` — правильно); `runtime/python` в PATH лаунчеров — мёртвый код; проба
   занятости порта есть только в PS-лаунчере и Swift.

## Проверка после правки

- Синтаксис: `zsh -n <файл>` / `bash -n <файл>` локально, затем полный
  `./scripts/verify.sh`.
- Помни: **Linux-установщик не исполняется в CI** (только `bash -n`), ветки
  Ollama/systemd/apt проверяются только вручную на сервере. Windows-скрипты в
  CI только парсятся. Реально исполняются в CI лишь macOS- и Windows-smoke в
  `release.yml`.
- Идемпотентность — часть контракта: повторный запуск установщика обязан
  сохранять пользовательский `home/settings.yaml`, пресеты и сторонние плагины
  (это проверяет release-smoke; не ломай).
