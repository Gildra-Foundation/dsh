# Обновление плагина в Gildra DSH

`config/kit.json` — единственный источник состава сборки. Установщики, workspace,
cordis-patch и пресеты генерируются из него; ручная правка версий где-либо ещё
либо упадёт на guard-проверках, либо молча разъедется с поставкой.

## Процесс

1. **Правь `config/kit.json`.** Формат пина: npm-пакет — точная версия
   (`dsh-foo@1.2.3`), GitHub-пакет — commit SHA (`github:owner/repo#<sha>`).
   Диапазоны (`^`, `~`) и ветки без коммита валидатор пропустит, но они ломают
   воспроизводимость — не используй их. Для свежего npm-пакета, который нужен
   раньше карантина новых релизов, добавь `"minimumReleaseAgeExclude": true`
   осознанно и упомяни это в PR.
2. **Обнови lock:** `node scripts/update-profile-lock.mjs` из корня репо.
   Скрипт прогоняет sentinel-аудит новых пакетов и пересобирает
   `config/profile/pnpm-lock.yaml`. Убедись в diff, что в lock появилась запись
   именно твоего пакета: проверка «плагин уже в lock» ищет подстроку
   `specifier: <версия>` без имени пакета (`scripts/kit-config.mjs:153-158`),
   поэтому совпадение версии с чужой может молча пропустить sentinel-аудит.
3. **Прогони `./scripts/verify.sh`.** Если упал тест в
   `scripts/kit-config.test.mjs` — смотри раздел «Растяжки» ниже, прежде чем
   что-то менять.
4. **Синхронизируй README вручную.** Раздел «Полный состав» в `README.md`
   (свёрнутый блок `<details>`) — ручной список версий, который ничем не
   сверяется автоматически. Обнови строку своего плагина (или добавь новую) —
   иначе документация начнёт врать, и это никто не поймает.
5. **Допиши `CHANGELOG.md`** в раздел `[Unreleased]`.

## Растяжки в тестах — обновляй, не «чини»

`scripts/kit-config.test.mjs` намеренно хардкодит отдельные значения как
сигнальные растяжки: версию дистрибутива (`:26`), версии Ollama (`:27-28`),
`dsh-doublecheck@0.8.0` в проверке workspace (`:58`). Падение такой строки при
бампе — ожидаемое поведение: обнови значение в тесте на новое. Не удаляй
ассерты и не делай их «гибкими» — их смысл в том, чтобы бамп был осознанным.

## Чего не делать

- Не вписывай спеки плагинов в установщики — `verify.sh` грепает
  `install/macos-install.command` и `install/windows-install.ps1` и упадёт.
- Не правь `config/profile/pnpm-lock.yaml` руками — только через
  `update-profile-lock.mjs`.
- Локальные плагины (`link:`-спеки: ui-compact, skill-installer, codegraph)
  версионируются своими `package.json` — их бамп не требует lock-регенерации,
  но изменение `client.js` требует поднять версию ui-compact (см. скилл
  `client-feature`).
