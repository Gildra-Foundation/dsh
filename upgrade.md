## 1. Вердикт

**Ядро спроектировано лучше, чем у большинства дистрибутивов такого масштаба.** Единый манифест `config/kit.json` с машинными guard-тестами, трёхслойная архитектура с документированными границами, работающий `verify.sh` и настоящие E2E-установки в CI — редкий фундамент. Все проверки при аудите прошли, а два десятка версий из README точно сходятся с манифестом.

**Но у сборки три критических дефекта и один системный разрыв.** Самообновление на Windows неработоспособно из-за неверного вызова PowerShell; Windows-установщик фиксирует упавшую установку как успешную; UI-плагин крутит вечную рендер-петлю на частоте кадров у каждого пользователя. Системный разрыв — в главной цели: проект, собранный «для разработки с помощью ИИ», не даёт ИИ-агенту ни `CLAUDE.md`, ни `npm test`, ни линтеров, а его тесты привязаны регексами к тексту исходника и краснеют от любого безопасного рефакторинга.

## 2. Критические дефекты

### C1. Самообновление на Windows неработоспособно

`scripts/gildra-update.mjs:245-248, 215-219, 349-353`

Все три вызова PowerShell построены как `powershell.exe -Command '…$args[0]…' арг1 арг2`. С `-Command` всё после строки команды приклеивается к её тексту, а `$args` остаётся пустым — он заполняется только с `-File`. `Expand-Archive` получает `$null` вместо пути плюс лишние позиционные токены → binding error → обновление падает всегда (к счастью, до остановки приложения — данные целы, но функция мертва). Не всплыло, потому что `applyUpdate` не покрыт ни одним тестом, а CI цепочку обновления не гоняет.

> **Опасность наивного фикса:** в `stopApplication` пустой `$needle` превращает фильтр в `-like "**"` — совпадение с *любым* процессом. Если просто убрать «лишний» хвостовой аргумент, `Stop-Process -Force` пойдёт по всем процессам сессии. Чинить через `-File` с временным .ps1 (или `-EncodedCommand`), и начинать со `stopApplication`.

### C2. Windows-установка молча фиксирует провал как успех

`install/windows-install.ps1` (запуск: `windows-install.cmd:3` → Windows PowerShell 5.1)

`$ErrorActionPreference = 'Stop'` не действует на коды возврата нативных команд в PowerShell 5.1, а `$LASTEXITCODE` не проверяется ни разу во всём файле. Провал `corepack pnpm install`, сборки Harness или `configure-profile.mjs` не останавливает скрипт: битый stage переезжает в `source`, маркер `.gildra-kit-version` пишется безусловно — и апдейтер навсегда считает такую установку исправной. На macOS и Linux это закрыто `set -euo pipefail`; на Windows защиты нет вовсе.

### C3. Вечная рендер-петля в UI-плагине — фоновая нагрузка CPU у каждого пользователя

`plugins/gildra-dsh-ui-compact/lib/client.js:3040, 3138, 4368-4381`

`ensureEnvironmentSwitcher` на каждом проходе безусловно вызывает `renderEnvironmentBadge`, а тот безусловно присваивает `badge.textContent` — даже той же самой строке. Присваивание пересоздаёт текстовый узел → childList-мутация → MutationObserver → rAF → снова весь конвейер: 12 translate-проходов, TreeWalker по всем текстовым узлам body, принудительные reflow. Как только в сайдбаре появился бренд-слот, цикл крутится на частоте кадров всю сессию. Фикс дешёвый: хелпер «писать только при изменении» (сравнение перед присваиванием) во всех `render*`-функциях.

## 3. Высокий приоритет — 17 находок

### Обновление и установка

- **[High]** `.github/workflows/ci.yml:39-43` — CI маскирует синтаксические ошибки PowerShell: `[ref]$errors` перезаписывается на каждой итерации цикла, финальная проверка видит только последний файл. Ошибка в `Start-GildraDSH.ps1` пройдёт CI незамеченной; в `release.yml:62-65` парсится вообще один файл.
- **[High]** `scripts/gildra-update.mjs:1`, `scripts/sync-server-fleet.mjs:1` — недокументированный контракт standalone-копий: оба файла копируются в `~/.gildra-dsh/bin` и обязаны использовать только `node:`-модули. Ни комментария, ни проверки — рефакторинг «вынести дубли в kit-config.mjs» пройдёт все тесты и сломает уже развёрнутые апдейтеры у пользователей.
- **[High]** `scripts/kit-config.mjs:338` — `run()` включает `shell: true` для `*.cmd` без квотирования: путь Windows-пользователя с пробелом (`C:\Users\John Doe\…`) разрывает команду. CI не ловит — у runner'ов пути без пробелов.
- **[High]** `scripts/kit-config.mjs:153-158` — проверка «плагин уже в lock» ищет подстроку `specifier: <версия>` без привязки к имени пакета (`specifier: 0.2.0` уже встречается дважды). Новый плагин с «чужой» версией будет сочтён известным → sentinel-преаудит перед добавлением в дистрибутив молча пропускается.
- **[High]** `scripts/gildra-update.mjs:251-313` — никакой защиты от параллельных запусков: кнопка в UI + ручной `Update-GildraDSH` одновременно дадут два установщика, гоняющих `mv source ↔ backup` с разными PID и перетирающих `update-state.json` друг друга.
- **[High]** `scripts/gildra-update.mjs:199-223, 282` — остановка приложения «выстрелил и забыл»: по таймауту 15 с установка стартует поверх живого процесса; в ручном macOS-пути `--parent-pid` не передаётся вовсе, так что ожидания нет совсем.
- **[High]** `desktop/macos/build.sh:31` + `release.yml:45` + `macos-install.command:111` — релизное .app подписано ad-hoc, а установщик его *предпочитает*: после скачивания с quarantine-атрибутом Gatekeeper блокирует запуск («не удаётся проверить разработчика»). Нужна нотарификация либо всегда-локальная сборка.

## 4. Производительность

Установщики и серверная часть по скорости в норме; проблема сосредоточена в клиентском плагине и вокруг обслуживания:

- **Вечная петля рендера** (C3) — весь конвейер на частоте кадров. Даже без неё живые цифры системного монитора будят полный проход каждые 1–2 секунды.
- `client.js:4406-4419` — интервал 500 мс гоняет **12 полных translate-проходов без dirty-флагов**, даже когда ничего не менялось.
- `client.js:2198-2210` — `applyBrandHeadline` обходит TreeWalker'ом *все текстовые узлы body* на каждом проходе; в длинном чате это тысячи узлов.
- `client.js:3117-3136` — `syncEnvironmentPlacement`: чтение layout → запись стилей → повторный `getBoundingClientRect` = принудительный reflow каждый проход; `client.js:2975` пересобирает поддерево переключателя целиком, снова будя observer.
- `client.js:4009-4018` — при открытом попапе «Агенты» capture-слушатель scroll на window с `getBoundingClientRect` на каждый пиксель прокрутки.
- `client.js:2920` — авто-SSH каждые 8 с ко всем серверам с бесконечными ретраями.
- `scripts/configure-profile.mjs` — каждый запуск всегда полный (pnpm install + npm install + перегенерация), хотя `manifestSha256` для short-circuit уже пишется в state — но нигде не читается (`kit-config.mjs:292-294`).
- `plugins/gildra-skill-installer/lib/index.js:110-121` — N+1 запросов к GitHub API (каждый файл отдельным `/contents`, хотя листинг уже содержал `download_url`): без токена лимит 60 req/час съедается одним средним скиллом.
- **След установки: 2,8 ГБ**, из них `downloads/` бессрочно хранит 60 МБ отработанных архивов; `windows-install.ps1:21,33` — `Invoke-WebRequest` в PS 5.1 без `$ProgressPreference='SilentlyContinue'` замедляет большие скачивания в разы.

## 5. AI-пригодность: главный вопрос сборки

### Что уже работает на ИИ

- `config/kit.json` — настоящий единый источник правды: workspace, cordis-patch и пресеты *генерируются* из него; «добавить плагин» = 1 правка + `node scripts/update-profile-lock.mjs`.
- Guard-тесты и растяжки: kit↔lock, kit↔Swift-RPC (с порядком!), kit↔overlay-features, запрет плагин-спеков вне манифеста, запрет тег-пинов GitHub Actions (`verify.sh:71-74`), сверка версии Info.plist.
- `docs/architecture.md` с правилами совместимости и `CONTRIBUTING.md` с чеклистом — хорошая «карта слоёв» для агента.
- Маленькие чистые функции со смысловыми именами в скриптах; комментарии в Swift объясняют *почему*, а не «что».

### Ранжированные барьеры

1. **Нет `CLAUDE.md`/`AGENTS.md`.** Агент, открывший репозиторий, не узнаёт ни про `verify.sh`, ни про слои, ни про запретные унификации. Минимальное содержимое: как проверять (`./scripts/verify.sh`), карта слоёв в 5 строк, инварианты (standalone bin-копии; тесты-растяжки с версиями; список мест синхронной правки при бампе), чего не делать (унифицировать три `parseArgs`, «чинить» захардкоженные версии в тестах).
2. **Нет корневого `package.json` и тулинга.** Нет `npm test`, нет ESLint/Prettier, shellcheck и PSScriptAnalyzer не запускаются нигде — единственный «линт» это проверка синтаксиса. Для JS-кода на ~7 тыс. строк это означает: ИИ-правки проверяются только глазами.
3. **Тесты, привязанные к тексту исходника.** `plugins/gildra-dsh-ui-compact/test.mjs:54-109` — ~60 `assert.match(clientSource, /…/)`; `scripts/kit-config.test.mjs:117-121` вырезает `OVERLAY_FEATURES` регексом между якорями. Любой безопасный рефакторинг краснит CI при сохранённом поведении — это *главный* тормоз ИИ-правок. Плюс захардкоженные `0.1.15` и версии в `kit-config.test.mjs:26-27,58` без пометки «растяжка».
4. **Невидимые инварианты.** Standalone-контракт bin-копий; маркер `id: gildra-ui-compact` в `configure-profile.mjs:142`; список фрагментов в `verify.sh:57-61` (60/70 уже не линтуются пофрагментно) — файлы связаны нитями, которых не видно из кода.
5. **Тройная реализация установщика** (zsh/bash/PowerShell) уже дрейфует: staging Node есть только на Linux, guard небезопасного корня обходится хвостовым слэшем на двух платформах из трёх, мёртвый `runtime/python` в PATH трёх обёрток из четырёх.
6. **Дублирование констант.** Порт 3080 — в 9 местах, 11434 — в 6, путь `source/apps/cli/lib/bin.js` — в 8, версии node/pnpm — в 3 workflow параллельно kit.json, RPC-список манифеста дублирует Swift-enum. Каждая — точка рассинхрона при ИИ-правке.
7. **README «Полный состав»** — ручной параллельный список ~20 версий, который ничем не сверяется. Сегодня сходится идеально — но это дисциплина, а не инструмент; дешёвый фикс — генерация из kit.json или grep-сверка в verify.sh.
8. **Монолит `client.js`: 4 440 строк в одной фабрике** (~1 000 строк CSS + ~1 200 словари + ~2 200 логики, базовый отступ 4+). Edit-инструментам трудно находить уникальный контекст в море похожих словарных строк. Реалистичная декомпозиция: (а) build-шаг (esbuild/конкатенация из `src/client/*` → `lib/client.js`, встраивается прямо в verify.sh) либо (б) минимум без инструментов — таблица `TRANSLATION_SURFACES` вместо 8 клонов translate-функций, единый реестр upstream-селекторов наверху файла, словари за баннерами в конце.
9. **Гигиена.** 8 скриншотов и 2 рабочих отчёта в корне репо; `script/` рядом со `scripts/`; RU/EN-смесь строк в одних файлах; устаревший комментарий `agent.cordis.yml:200-203`, который прямо предлагает редактору неверное действие (провайдеры давно включены).

## 6. Тесты и CI

**Зелёное:** все 6 сьютов проходят; `kit-config.test.mjs` — лучший (чистые функции + инварианты консистентности); в `release.yml` — настоящие E2E smoke-установки на macOS и Windows с проверкой повторного запуска и сохранности пользовательских данных; GitHub Actions запинены по commit SHA с самопроверкой.

**Дыры покрытия (ровно на самых рискованных путях):**

- `applyUpdate` — 0%: скачивание, SHA-сверка, распаковка, stop/restart, переходы state, откат — не покрыто ничем (здесь и жил C1; инфраструктура фейкового fetch в тестах уже есть — достроить недорого).
- `configure-profile.mjs` — главный оркестратор без единого юнит-теста (только косвенный CI-smoke при релизе).
- Симлинк-защита — без симлинк-тестов; `installBundle` скилл-установщика (атомарность, backup, отказ по симлинку) — 0%.
- Весь клиент — 0% исполняемых проверок (только регексы по тексту); негативные ветки `validateManifest` — 0%; fleet-sync при недоступном сервере — 0%.
- CI: Linux-установщик *никогда не исполняется* (только `bash -n`); тесты апдейтера и fleet-sync не гоняются на Linux-джобе; парсинг PowerShell маскирует ошибки; цепочка обновления не имеет E2E нигде.

## 7. Безопасность

**Сильные стороны, которые стоит сохранить:** SHA-256 для Node (5 платформ) и Ollama; commit-пины GitHub-плагинов; sentinel-преаудит новых пакетов перед добавлением в lock; замкнутый SHA256SUMS-контур обновлений; RPC-мост с origin-гейтом и whitelist-методами (валидация образцовая); XSS в client.js не найден — динамика везде через `textContent`; секретов в репо нет; SSH-fleet с параноидальной валидацией целей и staging-путей.

**Слабые места сверх перечисленных в High:**

- **[Med]** `patches/workspace-files-explorer-index.js:55→98-103` — TOCTOU: realpath-проверка и последующие `stat`/`readFile` работают по строке пути; подмена компонента симлинком между ними выводит чтение за root. На десктопе same-user, на сервере превью выключено — потому Medium, но заявленная гарантия строго не выполняется. Фикс: `open()` + `fstat`/чтение по fd.

## 10. Методика и охват

Аудит выполнен четырьмя параллельными ревью по зонам: клиентский плагин (client.js прочитан целиком), скрипты оркестрации, установщики + Swift-оболочка + CI, манифест + патчи + skill-installer + документация. Каждый файл зоны прочитан полностью; отдельные утверждения проверены экспериментально (обход guard хвостовым слэшем, поведение `ditto --keepParent`, разбор tree-URL с веткой-слэшем, покрытие integrity в lock-файле). Сверка версий README↔kit.json↔lock: 20+ утверждений, расхождений не найдено.
