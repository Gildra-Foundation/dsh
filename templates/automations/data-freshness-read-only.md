# Проверка свежести данных

Проверь, появились ли в проекте новые валидные данные, не изменяя файлы и внешние системы.

1. Определи ожидаемый источник, время последнего успешного обновления и обязательные срезы данных.
2. Не считай HTTP 200 достаточным успехом: проверь источник, объём, свежесть, структуру и целостность результата.
3. Сравни кандидата с последним корректным набором данных или LKG.
4. Не публикуй кандидата, не меняй конфигурацию, не устанавливай зависимости и не выполняй commit, push или deploy.
5. Если данные свежие и валидные, перечисли доказательства. Если нет — укажи точную причину, затронутые источники и безопасный следующий шаг.

Рекомендуемые параметры: `read-only`, запуск после ожидаемого обновления источника.
