# Gildra DSH Kit

[![CI](https://github.com/Gildra-Foundation/dsh/actions/workflows/ci.yml/badge.svg)](https://github.com/Gildra-Foundation/dsh/actions/workflows/ci.yml)
[![Release](https://img.shields.io/github/v/release/Gildra-Foundation/dsh?display_name=tag&sort=semver)](https://github.com/Gildra-Foundation/dsh/releases)
[![License: MIT](https://img.shields.io/badge/license-MIT-2ea44f.svg)](LICENSE)

**Gildra DSH** — воспроизводимая инженерная сборка DeepSeek Harness из исходников для локальной и серверной разработки на macOS, Windows и Linux. В одном desktop-приложении объединены агенты, пресеты, терминал, браузер, MCP, Skills, автоматизации, GitHub, карта кода и быстрый переход между локальным компьютером и SSH-серверами.

Комплект устанавливает отдельное окружение в домашний каталог пользователя и не переносит пароли, OAuth-сессии, токены, историю чатов или приватные рабочие файлы. Версии Harness, Node, Ollama, CodeGraph и управляемых плагинов закреплены в едином манифесте.

## Установка

### macOS

Скачайте архив `Gildra-DSH-macOS.zip`, распакуйте и дважды нажмите `Install Gildra DSH.command`.

Окружение устанавливается в `~/.gildra-dsh`, приложение — в `~/Applications/Gildra DSH.app`. Сборка подписана ad-hoc и не нотарифицирована: для публичного распространения без предупреждения Gatekeeper нужен сертификат Apple Developer ID и notarization.

### Windows

Скачайте `Gildra-DSH-Windows.zip`, распакуйте и запустите `Install Gildra DSH.cmd`. Установщик скачает закреплённый portable Node.js, исходники Harness и плагины, затем создаст ярлык **Gildra DSH** на рабочем столе.

CodeGraph включается автоматически, если найден `python3` на macOS или `python` в Windows. Без Python остаётся доступен Archify.

### Linux-сервер

Распакуйте серверный архив и запустите `./install/linux-server-install.sh`. Установщик скачивает закреплённые Node, Harness и Ollama, проверяет архивы по SHA-256, собирает тот же managed-профиль, при необходимости доставляет стандартные Debian build tools для нативного терминала, загружает локальную модель `nomic-embed-text` и оставляет web-интерфейс и embeddings API только на `127.0.0.1`. Ollama работает как пользовательская служба `gildra-ollama.service`; для постоянной работы после выхода из SSH администратор один раз включает linger для пользователя. Подключение выполняется из desktop-приложения через **Сервер SSH**; публиковать порты 3080 или 11434 в интернет не нужно.

На сервере каждому сотруднику рекомендуется отдельный Unix-пользователь и отдельный Git worktree. Общий `config/kit.json` остаётся одинаковым, а сессии, RAG-индекс, SSH-ключи и credentials хранятся раздельно. Для второго пользователя задайте свободный порт один раз, например `GILDRA_DSH_PORT=3081 ./install/linux-server-install.sh`; установщик сохранит его в пользовательской конфигурации. Уже работающий Ollama на `127.0.0.1:11434` автоматически используется как общий сервис, поэтому модель embeddings не дублируется для каждого сотрудника.

В desktop-приложении локальные и удалённые среды находятся отдельными разделами слева. Настроенные серверы подключаются в фоне при запуске, поэтому переход обычно сводится к одной быстрой навигации без ожидания нового SSH-сеанса. Повреждённый или зависший туннель автоматически пересоздаётся. Пункт **Этот компьютер** возвращает в локальный Harness без перезапуска приложения. При свёрнутой панели удалённая среда остаётся видна в компактной плашке `Сервер · имя`.

На рабочем Mac настроены две стабильные среды:

| Имя в приложении | SSH alias | Локальный туннель |
| --- | --- | --- |
| **Manacost** | `debian-151` | `127.0.0.1:55775` |
| **Gildra** | `debian-51` | `127.0.0.1:55776` |

Список хранится в пользовательском `~/.gildra-dsh/home/remotes.json`, поэтому не переносит SSH-ключи и не навязывает эти хосты другим сотрудникам.

Чтобы получить карту проекта, попросите: «Используй Archify и построй карту этой кодовой базы». После проверки Archify ИИ автоматически отправит готовый локальный HTML во вкладку **Карта кода** рядом с «Чат» и «Траектория». Удалённые URL в предпросмотре запрещены: карта открывается только из проверенного HTML в рабочем проекте или из HTML, переданного самим ИИ.

## Обновление установленного приложения

Откройте боковую панель и нажмите **Обновления**. Приложение сравнит установленную версию с последним стабильным выпуском `Gildra-Foundation/dsh`. Если обновление доступно, оно скачивается, сверяется с `SHA256SUMS.txt`, устанавливается и автоматически перезапускает Gildra DSH.

Для установки, в которой кнопки **Обновления** ещё нет, один раз скачайте свежий архив и запустите **Update Gildra DSH.command** на macOS или **Update Gildra DSH.cmd** на Windows. После этого следующие обновления доступны прямо из приложения. Повторная установка также считается безопасным обновлением и не создаёт второе окружение.

При обновлении сохраняются `home/settings.yaml`, авторизации, сессии, проекты, пользовательские пресеты, Skills, MCP и сторонние плагины пользователя. Управляемые Gildra-плагины, Harness, language servers и desktop-оболочка приводятся к версии из `config/kit.json`.

После установки или обновления на macOS комплект автоматически синхронизирует управляемую конфигурацию со всеми серверами из `remotes.json`: Manifest, профильные fragments, Gildra-плагины, пресеты, Skills, MCP и автоматизации. На сервер не копируются локальные авторизации, SSH-ключи, сессии, проекты, RAG-индекс и пользовательские настройки. Недоступный сервер не блокирует локальное обновление; повторная синхронизация выполняется следующим обновлением или вручную командой `node ~/.gildra-dsh/bin/sync-server-fleet.mjs --repo-dir <папка-комплекта> --install-root ~/.gildra-dsh`. Для диагностической локальной переустановки синхронизацию можно один раз пропустить через `GILDRA_DSH_SKIP_REMOTE_SYNC=1`.

## Первый запуск

При первом открытии выберите **English** или **Русский**. Выбор сразу применяется ко всему интерфейсу и сохраняется для следующих запусков; позже его можно изменить в **Настройки → Общие → Язык**.

Откройте **Settings → Subscriptions** и войдите в Codex и/или Claude. Учётные данные создаются отдельно на каждом компьютере и никогда не находятся в репозитории.

В боковой панели рядом с кнопкой добавления папки находится кнопка **Добавить репозиторий по ссылке**. Вставьте HTTPS-ссылку и при необходимости измените имя локальной папки. Для приватного репозитория заранее настройте доступ Git на этом компьютере; пароли и токены в ссылке приложение не принимает.

Чтобы включить перевод, откройте **Settings → General → Language → Русский**. Выбор сохраняется после перезапуска приложения.

В **Настройки → MCP/Навыки** можно просканировать Codex и Claude Code и выбрать, какие навыки или MCP-серверы перенести. Установленные сторонние плагины обнаруживаются в **Настройки → Плагины агентов**; импорт запускается только вручную, чтобы неизвестные hooks и расширения не начали выполняться без проверки.

В **Настройки → Навыки** можно вручную управлять локальными Skills. Также достаточно попросить ИИ: «Найди Skill для проверки API и установи его». ИИ найдёт точную папку на GitHub, проверит структуру и рискованные шаблоны, после чего приложение покажет источник, ревизию и SHA-256. Без нажатия **Установить** файлы не меняются; скрипты Skill во время установки не запускаются.

В **Настройки → Пресеты агента → Создать пресет** задайте роль, системный промпт, модель и глубину рассуждения. Новый пресет появляется в переключателе над полем сообщения; закреплённая модель применяется сразу при его выборе в пустой сессии.

В том же списке доступны четыре готовых режима проверки: **Ревью кода** ищет дефекты и регрессии, **Производительность** требует измерений до оптимизации, **Чистый код** проверяет понятность и сопровождаемость, а **Архитектура и модули** находит смешение ответственностей, циклические зависимости и чрезмерно большие файлы.

Для большой задачи попросите главного агента создать команду и раздать роли, например: «Создай команду из архитектора, разработчика и тестировщика, разбей задачу и веди общую доску». После первого `team_spawn` появится вкладка **Команда агентов** со статусами участников, задачами, перепиской и общими заметками.

GitHub-интеграция сначала использует локальную авторизацию `gh`. Если сотрудник ещё не вошёл, достаточно один раз выполнить `gh auth login`; альтернативно токен можно сохранить в защищённом хранилище через **Настройки → Плагины → GitHub**. Секрет не попадает в `settings.yaml`, установщик или репозиторий. Для просмотра исходников откройте рабочую сессию и нажмите **Файлы проекта** в её заголовке.

Автоматизации доступны из одноимённой кнопки в боковой панели сразу после запуска приложения — открывать чат предварительно не нужно. Сначала запускайте новую задачу кнопкой **Запустить сейчас** и проверяйте результат. Для фонового исправления кода используйте `workspace-write`; `danger-full-access` выбирайте только вручную для полностью доверенных задач.

Раздел **Настройки → Плагины → Контрольные точки** показывает историю снимков и разницу между ними. Команда `/checkpoint` создаёт точку вручную, а `/rewind <id>` показывает план отката и запрашивает подтверждение. Кнопка **ИИ-ревью** в заголовке сессии показывает решения независимой проверки. LSP-инструменты подключаются автоматически по расширению файла и не требуют настройки в каждом проекте.

Терминал раскрывается сочетанием `Ctrl+\`` или из нижней панели. В **Настройки → Плагины → MCP** доступны состояние серверов и пробные вызовы. Для браузерной автоматизации сначала попросите ИИ проверить `browser_status`; если Chromium ещё не установлен, подтвердите одноразовый вызов `browser_install`. Авторизации браузера и Context7 API key настраиваются только локально.

Готовые безопасные шаблоны находятся в [`templates/automations`](templates/automations).

## Обновление и воспроизводимость

Единственный источник версий, плагинов, language servers и разрешённых install-скриптов — [`config/kit.json`](config/kit.json). Профиль собирается из небольших файлов в [`config/profile/fragments`](config/profile/fragments), а транзитивные зависимости свежей установки закреплены в [`config/profile/pnpm-lock.yaml`](config/profile/pnpm-lock.yaml).

Границы между Kit Manifest, нативным Desktop Host и Harness Overlay описаны в [`docs/architecture.md`](docs/architecture.md). Новые системные функции добавляются через версионированный Host RPC, а интерфейсные функции — в одну из именованных Overlay feature-групп.

После загрузки Node оба установщика передают управление одному [`scripts/configure-profile.mjs`](scripts/configure-profile.mjs). Повторный запуск:

- обновляет Node, Harness и CodeGraph при изменении версии или commit;
- сверяет SHA-256 архивов Node и серверного Ollama;
- приводит Gildra-managed плагины к манифесту и фиксированному порядку Bundle-слоёв;
- удаляет только устаревшие управляемые пакеты, сохраняя плагины пользователя;
- создаёт пользовательский `settings.yaml` только при первой установке и не перезаписывает последующие настройки;
- заново собирает управляемый `cordis.patch.yml` и проверяет его через `dsh --dump-config`;
- записывает версию комплекта и устанавливает внешний updater, который может безопасно перезапустить работающий desktop-процесс.

Для изменения сборки отредактируйте `config/kit.json` или нужный профильный fragment. Списки плагинов в macOS и Windows установщиках больше не дублируются.

После изменения версии или состава плагинов обновите закреплённые транзитивные зависимости командой `node scripts/update-profile-lock.mjs`, затем запустите `./scripts/verify.sh`.

Workflow [`check-upstream.yml`](.github/workflows/check-upstream.yml) раз в неделю сравнивает нашу закреплённую версию с официальным npm-пакетом `@deepseek-ai/dsh`. Новая версия Harness не ставится сотрудникам напрямую: сначала создаётся отдельный PR с новым commit, обновлённым lock-файлом и полной проверкой совместимости. Доставка начинается только после review, merge и выпуска тега, совпадающего с `distribution.version`.

## Проверки

```bash
./scripts/verify.sh
```

Проверка валидирует единый манифест, соответствие lock-файла, профильные fragments, JavaScript, shell-скрипты и собирает macOS app. GitHub Actions дополнительно разбирает PowerShell, дважды выполняет чистую установку на macOS и Windows и проверяет итоговый профиль перед созданием архивов.

## Безопасность

- В репозитории нет `.dsh` пользователя, credentials, cookies, session logs или рабочих проектов.
- MCP-токены и заголовки не синхронизируются автоматически: выбранный импорт сохраняет их локально открытым текстом в конфигурации профиля, поэтому включайте только доверенные MCP-серверы.
- Обнаружение Codex/Claude plugins работает в режиме чтения. Копирование и активация конкретного плагина выполняются только после явного выбора пользователя.
- Поиск плагинов возвращает рекомендации и команды установки, но не выполняет их автоматически. Перед добавлением нового пакета проверяйте источник, закрепляйте версию и прогоняйте полный профиль.
- Удалённый Harness слушает только loopback-интерфейс и открывается через SSH-туннель. Не выставляйте порт 3080 через firewall или reverse proxy.
- Браузер запускается в режиме `standard`: действия на странице требуют подтверждения, login state отсутствует, автоматическая загрузка Chromium отключена, а сетевой postinstall OpenCLI явно запрещён.
- Автоматизации по умолчанию ограничены домашним каталогом пользователя; для обычных проверок используйте `read-only`, для локальных исправлений — `workspace-write`.
- Никакой автоматический commit, push, deploy, DNS-операции или вызов платного провайдера не включены по умолчанию.
- Updater принимает только стабильный release из `Gildra-Foundation/dsh`, требует платформенный архив и опубликованную SHA-256 сумму. Прямая установка непроверенного upstream Harness отключена.
- Операции записи GitHub (создание/изменение PR и issues, комментарии, merge) проходят через отдельное подтверждение в DSH; чтение репозитория и файлов остаётся read-only.
- Автоматическое восстановление парсера — одна ограниченная попытка с сохранением LKG и обязательной валидацией результата.

DeepSeek Harness и сторонние плагины сохраняют собственные лицензии. Desktop-оболочка основана на MIT-проекте `Carleo10032/deepseek-harness-mac`.
