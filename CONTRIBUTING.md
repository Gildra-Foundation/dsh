# Как участвовать в разработке

Спасибо за вклад в Gildra DSH. Проект ценит небольшие, проверяемые изменения, которые сохраняют пользовательские данные и совместимость с upstream DeepSeek Harness.

## Перед изменением

1. Прочитайте [архитектуру](docs/architecture.md) и найдите владельца слоя: Manifest, Desktop Host или Harness Overlay.
2. Не дублируйте версии плагинов в установщиках — их единственный источник находится в [`config/kit.json`](config/kit.json).
3. Не добавляйте credentials, `.dsh`, сессии, приватные проекты или SSH-ключи.
4. Для нового стороннего пакета закрепите точную версию или commit и проверьте install-скрипты.

## Проверка изменения

```bash
./scripts/verify.sh
```

Для интерфейсного изменения дополнительно проверьте реальное desktop-приложение: первый экран, изменённое действие, ошибки консоли и состояние после перезапуска. Скриншот должен показывать фактическую сборку, а не макет.

Для установщиков проверьте повторную установку: пользовательские настройки, пресеты и рабочие файлы должны сохраниться.

## Pull request

- Опишите проблему и пользовательский результат.
- Перечислите проверки и намеренно не выполненные внешние действия.
- Добавьте скриншоты для видимых изменений.
- Не смешивайте функциональное изменение с несвязанным рефакторингом.
- Не создавайте release-тег: выпуск выполняет maintainer после успешного CI и проверки версии манифеста.
