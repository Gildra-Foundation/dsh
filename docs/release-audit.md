## Исправленные проблемы

1. Полностью переведены Automations, SSH-настройки и динамическое содержимое Context Doctor.
2. Убран конфликт слоёв: свёрнутый `dsh-top` больше не перекрывает кнопку выхода из автоматизаций и Context Doctor.
3. В удалённой среде показывается весь список серверов, поэтому Manacost и Gildra переключаются напрямую.
4. Адрес возврата из SSH-среды ограничен loopback HTTP-адресами; произвольный внешний URL больше не принимается.
5. SSH-цель не может начинаться с опции, а удалённый порт проверяется в диапазоне `1024–65535`.
6. macOS, Linux и Windows установщики отказываются работать с корнем диска или домашним каталогом как install root.
7. GitHub Release больше не использует изменяемый сторонний action с правом `contents: write`; публикация выполняется штатным `gh`.
8. `CFBundleVersion` desktop-приложения теперь совпадает с версией Kit, а локальный UI-плагин получил новую версию для корректного обновления браузерного кэша.
9. Свёрнутый системный монитор больше не висит поверх стартового экрана широкой плашкой: он занимает компактные 30×30 px, имеет понятную подпись для клавиатуры и раскрывается тем же действием.

## Качество и безопасность

- `./scripts/verify.sh` проверяет JavaScript, shell, YAML, манифест, lock-файл, updater, серверную синхронизацию, плагины, macOS-сборку, подпись и `Info.plist`.
- Production-аудит установленного pnpm-профиля: известных уязвимостей не найдено.
- Поиск секретов не обнаружил сохранённых токенов, паролей, приватных ключей или сессий.
- Host RPC доступен только главному loopback-окну и содержит ограниченный список методов.
- Updater требует платформенный архив и опубликованный SHA-256.
- Skill-установщик ограничивает источник GitHub, размер и глубину, проверяет рискованные конструкции, не запускает скрипты и всегда запрашивает подтверждение.

Стандартный security scan завершён без открытых находок. Во время прохода рабочее дерево менялось из-за исправлений, поэтому финальный diff дополнительно проверен тестами и повторным живым пользовательским путём. Независимый параллельный аудитор в текущем runtime был недоступен; проверка выполнена последовательно.

## Намеренно не выполненные внешние действия

Следующие функции проверены по интерфейсу, конфигурации и защитным границам, но не запускались, чтобы не создавать реальные данные и расходы:

- OAuth-входы Codex, Claude и GitHub;
- создание pull request, merge, deploy или публикация issue;
- клонирование внешнего репозитория;
- создание и запуск реальной фоновой автоматизации;
- установка Chromium и сохранение browser login state;
- запуск и остановка Docker Compose;
- применение обновления поверх работающей сборки;
- destructive rewind или команды с `danger-full-access`.

Эти сценарии требуют отдельного тестового аккаунта или проекта и явного подтверждения пользователя. Их наличие в интерфейсе не считается доказательством внешней доставки.

## Релизная граница

Push в `main` публикует исходную конфигурацию и запускает CI. Установочные архивы появляются только после отдельного тега `v<distribution.version>`, совпадающего с версией в `config/kit.json`. Перед тегом `v0.1.15` необходимо дождаться зелёного CI и синхронизировать управляемый профиль на настроенные серверы. Этот аудит не создаёт релизный тег автоматически.
