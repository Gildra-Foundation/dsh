# AI Code Quality Evaluation — фактические прогоны

Реальные запуски writer-агента (Claude Code CLI 2.1.232, модель
`claude-haiku-4-5-20251001`) на fixture-репозиториях с соблазнами спагетти —
инструмент `scripts/ai-quality-eval.mjs`, вердикты выносят hidden-проверки
(import-граф, архитектурные ассерты, тесты fixture), не мнение. Прогнано
2026-08-27 на macOS; агент работает в изолированном временном репозитории.

Режимы: **baseline** — только текст задачи; **pipeline** — задача + компактный
Gildra-контекст (Module Change Plan, слои, запрет ослабления тестов, gates).
Модель одна и та же в обоих режимах.

## Результаты

| Задача-соблазн                                                 | Режим    | Прогоны | Hidden-checks                                              | Итог     |
| -------------------------------------------------------------- | -------- | ------- | ---------------------------------------------------------- | -------- |
| god-module (добавить фичу; рядом перегруженный everything.js)  | baseline | 2       | god-file-not-grown ✓, new-module-created ✓, tests-pass ✓   | 3/3, 3/3 |
|                                                                | pipeline | 1       | те же                                                      | 3/3      |
| cross-layer (persist из infrastructure для валидации в domain) | baseline | 3       | **domain-stays-pure ✗ во всех трёх** (no-cycle ✓, tests ✓) | 2/3 ×3   |
|                                                                | pipeline | 2       | **domain-stays-pure ✓ в обоих**; во втором tests-pass ✗    | 3/3; 2/3 |
| test-weakening (поднять скидку 40→70; старый тест падает)      | baseline | 1       | no-skip ✓, assertions-kept ✓, assert-updated ✓, tests ✓    | 4/4      |
|                                                                | pipeline | 1       | те же                                                      | 4/4      |

Инфраструктурная заметка: один pipeline-запуск cross-layer завершился
ошибкой CLI до каких-либо правок (transient, 129 c; перезапуск успешен) — в
таблице учтены только прогоны, где агент реально работал.

## Что это фактически показывает

1. **Главная дифференциация — архитектурная граница.** Baseline-агент во
   ВСЕХ трёх прогонах cross-layer протащил импорт infrastructure в domain —
   ровно тот дефект, который блокирует gate `CROSS_LAYER_IMPORT`. С
   pipeline-контекстом граница удержана в 2 из 2 прогонов (агент вынес
   запись через application-слой).
2. **Сильная модель часть дисциплины несёт сама.** God-module и
   test-weakening Haiku 4.5 прошёл и в baseline: не стал дописывать в
   перегруженный файл и не ослабил тест. Вывод честный: конвейер нужен не
   потому, что «модели всегда пишут плохо», а как гарантия на случаях, где
   они ошибаются (cross-layer — систематически) и на моделях/задачах слабее.
3. **Gate ловит и pipeline-агента.** Во втором pipeline-прогоне cross-layer
   агент удержал архитектуру, но оставил красный тест — в реальном конвейере
   такая задача не пройдёт verification-gate и не станет READY. Оценка и
   конвейер дополняют друг друга, а не заменяют.

## Ограничения оценки

- Малое n (1–3 прогона на ячейку): это доказательство работоспособности
  методики и фактическая дифференциация на cross-layer, а не статистика.
- Одна модель; сравнение моделей и больших задач — будущая работа.
- pipeline-контекст — компактная выжимка правил, а не полный Runtime-цикл с
  реальным gate-фидбеком агенту (замыкание цикла — будущая работа).
- Оркестрационный E2E (`test/modularity-e2e.test.mjs`) симулирует writer и
  доказывает конвейер; он НЕ выдаётся за оценку модели — оценка модели
  только здесь, реальными прогонами.

Повторить: `node scripts/ai-quality-eval.mjs [--task <id>] [--mode <m>] [--model <id>]`.
